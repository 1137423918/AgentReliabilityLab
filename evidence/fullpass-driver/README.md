## 首次 GPU 对照的原始预声明

[原始协议指纹与调用上限](preregistration/manifest.json)、[协议](preregistration/protocol.json)、[资源与归属控制器](preregistration/continuation_controller.py)在运行前冻结。

固定Qwen2.5-3B-Instruct、种子42、reference分支、完整原始调度的前两次更新：19条+20条样本，4105监督标签、29431输入token。连续路径在一个进程完成两次更新；分段路径在另一个进程完成第一次更新并保存，退出后在第三个进程恢复并执行第二次更新。每次进程有标准CE/选择位置CE两次对照，不能隐去额外调用。

预算固定为84次逻辑前向（78次训练、6次对照）、78次反向、4次优化器更新，0次文本生成，无资源/质量重试。三个进程分别41/21/22次前向、2/1/1次更新。所有调用为独立数值控制成本，不属于完整研究权重或评测成绩。

逐次比较两条路径的训练损失、梯度范数、适配器哈希，以及最终权重张量文件、优化器/RNG张量文件与类型化状态元数据；要求逐位一致。轨迹身份和实际调用次数保持各自记录，不能覆盖或抹掉分段的额外对照成本。GPU不满足准入或对照失败时保留失败及扣额，不能改容差或重跑挑一个通过结果。

每个进程重新核对同一物理GPU的空闲观测、UUID、CPU/内存及归属；仅清理本任务PID+启动标识，外来算力进程触发停止。旧599/750/831次账本不变。对照通过后，完整3700样本×三种子×两分支仍需独立、按实际分段开销推导的训练额度；本协议不分配新题生成额度。主页继续冻结。

## 首次实际结果：严格比较失败

三个物理进程均正常退出，归属进程为0、自身GPU上下文已释放；但两条路径的训练状态不一致。[关闭回执](gpu-v1-failed/results/closure.json)、[严格比较失败](gpu-v1-failed/results/comparison.json)、[差异明细](gpu-v1-failed/results/diagnosis-metadata.json)均保留。实际84次逻辑前向已预留并完成，78次反向、4次优化器更新，未知为0，无重试，无文本生成。不能把进程成功退出写成数值对照通过。

初始适配器和第一次更新的前向损失一致，但第一次更新的梯度范数已经不同：连续1.5679255723953247，分段1.5679476261138916，差2.20537×10⁻⁵；更新后权重哈希也不同。此差异发生在任何恢复之前，因此没有证据把首个差异归因于检查点读取。第二次更新损失和权重进一步不同，不能放宽容差称为逐位一致。

该现象与默认GPU反向中的非确定性一致，但首次运行没有剖析实际选中的SDPA内核，不能断言单一内核就是已证明的唯一原因。[PyTorch2.6复现文档](https://docs.pytorch.org/docs/2.6/notes/randomness.html)要求控制随机源之外还要控制非确定性算法；其[2.6 Flash反向源码](https://github.com/pytorch/pytorch/blob/v2.6.0/aten/src/ATen/native/transformers/cuda/attention_backward.cu#L90-L99)提供显式确定性路径。
