# Bounded MCP audit cleanup after status failure

The adapter previously queried audit_status then close_audit in one try block, on the workflow transport. A status failure skipped close entirely. Cleanup now runs outside the workflow transport/deadline, using one fresh transport for the **same audit**: ten seconds total, optional status capped at two seconds, then one close attempt. It does not start another audit, renew TTL, refund unknown model attempts or replay tools. External cancellation still propagates.

The original fixture named status_error omits MCP2 resultType and is **malformed-response coverage**, not a valid tool error. Its result is retained. A separate single-case followup adds resultType=complete and verifies actual MCPToolFailure; baseline skips close and the unchanged candidate adapter closes. The previous nine scenarios are not repeated for that followup.

Original nine cases: baseline6pass/3fail, candidate9pass. The three baseline failures are **not three resource leaks**: malformed response skips close; delayed status already eventually closes; expired context is already inactive but no close was attempted. Normal acceptance, forged-fact rejection, unread-fact rejection, prose-only rejection, model deadline and external cancellation already pass on baseline. Valid-tool-error followup: baseline0pass/1fail, candidate1pass. The ten distinct candidate controls include the earlier four controls; no addition to the prior130 core-test snapshot.

Each side records21 scripted model POSTs across ten real MCP/LlamaIndex cases. Two interrupted requests per side remain charged unknown; zero neural requests or GPU usage. Every candidate case starts exactly one audit and attempts exactly one close. Expired context close correctly fails and is never reported as confirmed. All test server tasks end, all four execution profiles are terminal, no owned process remains, frozen source bytes and locked SDK distribution versions remain unchanged. No package installation, real-model rerun or production traffic.

The earlier real9B CPU600-second failure remains unchanged in evidence/mcp-agent. This fix does not turn it into a successful audit, renew a capability, resume a workflow, authenticate a user or provide an exactly-once guarantee. See docs/mcp-agent.md for runnable commands and explicit limits.
