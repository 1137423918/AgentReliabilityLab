# 完整文件清单任务：按图关闭目录查询

前一场真实ADK维护试验已经提供唯一生产文件路径，模型仍消耗四次请求逐级查询目录，随后继续读取符号，八次请求后无编辑。[原始失败记录](../evidence/adk-focused-cpu/README.md)保持原样。这里要验证的工程假设是：完整、已固定的文件任务可以直接使用清单路径，避免把目录发现作为必要前置步骤。是否改善真实模型结果仍需独立试验，接口检查不是模型能力成绩。

## 任务契约

在已有`required_features`中追加`file_inventory_v1`，保留原版测试、Python语法、模型预算等已有标志；其他任务配置不变。worker从校验后的`files`生成完整的根路径JSON清单，直接放入模型系统提示。清单最多8192字节UTF-8 JSON，超出就整份拒绝，不展示一个自称完整的截断列表。

新模式只关闭`ls`：每次模型请求的工具定义中不含它；如果模型仍发出`ls`，在调用后端前返回明确的`ToolMessage(status="error")`，让模型看到原因。`glob`仍可筛选路径，`grep`、`read_file`、`inspect_python`（若已启用）、编辑与写文件保持原接口。拒绝的工具调用仍属于本次图执行；此前模型请求已消耗的额度不会退回。

目录查询策略使用当前固定版本LangChain的公共`AgentMiddleware`按图创建。没有向模型全局`HarnessProfile`注册额外排除项，因此同一进程中的其他任务不继承该策略。默认不带新标志的任务沿用原有工具集。

这是执行与导航策略，不是新文件系统沙箱。最终只允许导出任务声明的文件、固定原版验收、语法检查、源码版本与请求守卫仍由既有worker执行。未允许新增文件、外部命令或委派。新标志本身进入现有完整任务哈希和预算身份；恢复时改标志会拒绝，不能借此清空或绕过额度。没有manifest格式迁移。

## 兼容与核验

实现针对固定Deep Agents0.7.41的worker内置工具图。读索引与新策略可以同时装配；只读检查器也重建同一无状态策略，不调用模型或工具。生产worker使用同步图执行；不能据此声称完成了异步代理或任意自定义SDK图的完整兼容矩阵。

服务器检查使用明确的假HTTP模型，验证真实线缆请求、后端调用探针、编辑及固定验收、同别名图隔离、SIGKILL恢复、持久额度、清单引号/Unicode和整份超限拒绝。组合场景要求读取回复保留既有首屏索引，不能因为新增中间件覆盖旧策略。检查结果与准备失败记录将在证据目录中分别保留，不累加为神经维护通过次数。

服务器最终完整回归106项通过、零跳过，六项专项包含在内；构建wheel的三个生产模块逐字节一致，实际console入口经假HTTP完成编辑与验收。[日志、源码哈希和准备失败](../evidence/file-inventory/README.md)分别保留。尚不能从这些接口检查推断真实模型收益。

## 独立真实模型结果

新[预声明ADK试验](../evidence/inventory-cpu/README.md)没有ls调用，但一次符号读取漏传哈希，随后继续read/grep，1525.938秒后八次请求用尽，仍无编辑/补丁/验收。接口契约与模型结果分别记录；没有证明耗时、token或修复收益，不放宽源码哈希。
