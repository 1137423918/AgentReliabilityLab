# 固定监督预算的 3B LoRA 试验

在真实工具调用数据上验证监督训练、检查点和评测链路。[前阶段](training-study.md)已经完成配对输入、文本关联分组、197 条 clean 开发集和 79 条原扰动验证。**Full、Mixed 均已实际执行 32 次更新。Full 原运行的训练后核验中断，保存检查点的独立回放已通过；Mixed 本轮完整核验通过。** 后续[真实生成与恢复评测](generation-recovery.md)已有新基线和部分 Full 结果，三组对照尚未完成。不将这次试验称为工具调用准确率提升或 ToolRL-DR 复现。

## 已发生的训练与缺口

Qwen2.5-3B-Instruct，固定 revision `aa8e72537993ba99e69dfaafa59ed015b17504d1`，原模型 3,085,938,688 参数，FP16、RTX 3090、原生 SDPA。Full 实际完成 32 次 AdamW 更新、65,536 个有效移位监督标签、774 个反向片段、573,843 个输入 token 暴露位置，并提交 step 8/16/24/32 四个私有检查点。持久化前向账本为 1,329 次预留、1,329 次完成、0 次未知；模型请求没有重试。

原控制器最终退出 2：`nvidia-smi` 监控连续超时，最后有效 GPU 数据超过 30 秒，按预先声明的保护停止自有模型进程。此时训练和全部训练前/后 teacher-forced 损失文件已经保存，但最后两个 canary 尚未完成，原进程最终冻结参数哈希和检查点重新加载验证也没有持久证据。**原运行保持失败；不能从“32 次更新已发生”推导“整场通过”。** 自有进程和 GPU 上下文已清理；没有终止其他用户的计算进程。

| Teacher-forced token 加权 NLL | 两组训练前 | Full step32 | Mixed step32 |
| --- | ---: | ---: | ---: |
| clean 开发，197 条 / 16,220 个标签 | 1.489357 | 0.277476 | 0.275333 |
| 原扰动验证，79 条 / 6,887 个标签 | 1.442288 | 0.297599 | 0.297934 |

这些损失使用参考 assistant 输出，包括格式和推理脚手架 token，**不是自由生成后的工具调用评分，也不是实际工具执行验收**。开发/验证来源仍是同一发布数据，文本分组没有证明语义或预训练隔离。Mixed 的开发损失略低，原扰动验证损失略高；单种子、每组 32 步的小预算结果没有显示验证损失优势。尚无完整同后端三组生成对照，不能据此判断扰动混合是否改善工具调用泛化。

## 实际训练配方

LoRA 仅作用于 `q_proj` / `v_proj`，rank 8、alpha 16、dropout 0、bias none；PEFT 默认初始化，附加前 seed 42、B 为零，训练参数为 FP32。固定 32 次更新，不根据开发/验证分数挑选检查点。

AdamW 学习率 2e-4、betas (0.9, 0.999)、eps 1e-8、weight decay 0、无调度器；梯度范数裁剪 1.0。GradScaler 初始 1024，非有限梯度或跳过更新即失败，无神经重试。非重入梯度检查点、关闭 cache 和 TF32。每次更新累积恰好 2,048 个有效标签，各片段 CE 求和除以 2,048，不再按片段数平均。

保留完整因果上下文，只选择移位标签对应的 logits。初始真实 3B 的标准 masked loss 与选择位置损失经过 canary 核对；零 B 适配器的初始输出也与原模型匹配。每步检查冻结参数梯度为空、可训练梯度有限、AdamW step 递增且适配器哈希变化。原进程最终冻结参数哈希缺口仍单列，不用这些逐步检查替代。

每 8 步原子提交 safetensors 适配器、优化器/Torch RNG 与 JSON 计数、scaler、文件清单。step32 五个文件的哈希已重读核验。**训练恢复尚未实现**；保存状态不等于已验证可从机器中断恢复，也不从零重跑来覆盖失败。权重、优化器状态、完整提示、答案、token 向量和 Parquet 均不公开。

Full/Mixed 的更新数与监督标签预算相同，但计划输入暴露、片段数和 ID 覆盖不同，不能称 FLOPs 完全相同。本次是固定预算 SFT pilot，未运行 GRPO。

## 后续核验与资源准入

独立核验已读取保存的 Full step32，额外优化器更新为零；277 次前向全部完成，重新构建的冻结基座和适配器指纹匹配，197 条开发与 79 条验证的每例损失与原保存结果完全一致，关闭适配器的基座 canary 也通过。它不能补写原进程缺失的最终内存指纹，也不能把原失败改判通过。核验子进程退出0，但监督器在退出边界触发 foreign-client 保护，整场仍失败；没有记录该判定对应 PID，故不能断言原触发根因。另用真实 Linux 子进程复现了旧集合差集把已退出的自有 PID 误判为外部的缺陷，六项 CPU 控制通过。修订用已记录的 PID/start_ticks 区分缓存退出、PID 重用和未知进程，保留全部资源保护；后续复用已完成核验，不重复这 277 次调用。

随后 Mixed 的首次 32 次更新已完成：65,536 个监督标签、772 个反向片段、537,483 个输入 token 暴露；前向 1,329 次全部完成。使用相同初始模型、适配器种子、监督预算与未改动的神经训练器，优化前指纹已匹配，两组训练前损失也相同。Mixed 最终冻结参数哈希、禁用适配器 canary、step32 重载哈希和 canary 均通过，控制器退出0，未触发保护；模型阶段455.992秒，整场479.411秒，自有进程0且GPU上下文消失。固定 step32 后再单独声明同后端 base/Full/Mixed 的官方 199 条 clean 生成评测，无反馈、修复或重试。

监控修订为隔离的、固定版本 NVIDIA NVML Python SDK，持续读取同一卡的缓存句柄；短测试已完成 8 个有效样本，未加载模型。不改变 foreign-client、30 秒 stale、22,528 MiB GPU、24 GiB RSS 等保护。选定 GPU 必须经过空卡双样本、UUID 建议锁及新鲜再检查；锁不构成调度器独占。若有其他计算进程则等待或退出。原卡等待 600 秒仍被占用，零新增模型调用；随后在 Mixed 首次优化前单独声明改用另一张同型号 RTX 3090（相同 sm86 / 驱动 / 运行时），先回放 Full32。两次训练物理卡不同，不声称完全相同设备的训练对照；后续三组生成评测仍要求在同一新卡和后端进行。当前进展以证据快照为准，不能将计划描述当作已通过核验。

## 复现入口与证据

依赖为 Linux / Python 3.11、PyTorch 2.6.0+cu124、Transformers 4.57.6、PEFT 0.18.0，独立锁见 [requirements.lock](../extras/lora-training/requirements.lock)。服务器先验证模型 revision/文件、数据 SHA、GPU 准入和监督协议，再运行：

```bash
# 输出目录必须全新；输入和协议须先独立验证，不自动恢复或重试。
python benchmarks/train_toolrl_lora.py \
  --model /path/to/verified-model \
  --data /path/to/verified-study \
  --output /path/to/new-private-output \
  --spec /path/to/frozen-protocol.json \
  --variant train
```

入口本身不提供资源监督；须配合已检查的服务器控制器。CPU 运行时复制/准备不等于 GPU 训练，监控短测试也不计模型调用。首次归档与准入失败、实际 Full 训练失败分别保留；原 199 条 P100 基线不重评分，既有 130 项核心测试不计为本阶段新增成绩。项目材料继续更新，个人主页保持冻结。
