# 把阅读结果整理成可分享的报告

研究助手完成运行后，可以关闭本地模型和MCP服务，再把一项或多项结果整理成Markdown阅读记录和JSON引用清单。报告包含问题、已有回答、来源链接、物理页码和未完成原因，适合整理论文阅读笔记或向同事交付结论。

报告只整理已保存的结果，不补写模型没有完成的回答，不重新检索或生成答案。原来未完成的任务仍标为未完成；如果运行文件或来源无法核对，该项单独显示导出异常，其余有效记录仍可导出。

## 使用

使用已安装的[研究助手CPU环境](../extras/research-assistant/README.md)，从仓库根目录执行：

```sh
extras/research-assistant/.venv/bin/python -m agent_lab.research_report \
  --run-dir /path/to/reading-question-001 \
  --run-dir /path/to/reading-question-002 \
  --store /path/to/paper-store \
  --output /path/to/new-reading-report
```

每个`--run-dir`应是本工具创建、写入进程已停止且SQLite连接已关闭的运行目录，包含`run.json`、`result.json`、`graph.sqlite`、请求账本和已保存回复。支持一次选择1–16项。不要把他人上传的未知数据库当作本地运行文件导入。

输出目录必须尚不存在，且位于输入运行和资料库之外；需要重新导出时选择新目录。成功输出：

- `reading-report.md`：便于阅读的问题、回答、页引用和失败说明，运行用量折叠显示。
- `reading-report.json`：完整来源版本、字符范围、原文/PDF哈希、原始任务状态和调用摘要，不含原文片段或模型完整通信。
- `report-manifest.json`：前两份文件的哈希与字节数，作为报告写入完成的标记。

原运行未完成不影响报告导出命令成功，报告会保留该状态。存在无法读取或核对的输入时，仍生成分项报告，但命令返回2；参数或文件写入失败则直接报错。导出中断后若未出现完整清单，应使用新目录重新导出。目录与文件默认仅当前用户可读写，分享前自行审阅问题及回答内容。

## 引用与失败如何处理

报告从运行身份对应的SQLite终态读取记录，并核对结果、请求账本和保存回复。它不会调用图的执行或恢复入口，也不会打开模型客户端、连接MCP或载入嵌入模型。SQLite以只读快照方式打开，不建表、不迁移；存在非空WAL、SHM或回滚日志时拒收。

对于已接受的回答，报告通过已安装的0.2.0资料服务库回读原引用，核对资料版本、原文字节哈希、字符范围和PDF页信息。原运行引用的版本仍在归档中时，当前资料库的活跃版本变化不会迫使报告改用新原文；链接会标注“归档版本”。引用读取与哈希一致不等于证明模型解释正确。

对于未接受的提交，只整理最后一次尝试和已有工具反馈。例如，模型选择“证据不足”却给出空回答并附引用时，报告会列出拒收原因，不把它改写成一次成功拒答。报告也不从草稿或原始回复中另选一个看似正确的答案。

这仍是单个操作者的本地工具。只读模式要求输入已经停止变化，不保证并发写入时的快照安全，也不提供多租户或任意未知数据库的隔离能力。输入已经缺失或没有终态时，报告不会通过重新运行任务来补齐。

## 验证范围

服务器新增9项工作流测试，使用真实LangGraph/SQLite、LlamaIndex索引及非神经夹具向量、脚本化回复；它们验证报告行为，不是模型回答质量。首次测试因夹具未建立请求目录而失败，修正后同组9项通过。原研究助手16项、全文导入21项测试没有为本次导出重新运行或累计计数。

已完成服务器真实应用联调：[阅读报告示例](../examples/research-reports/reading-report.md)整理上一轮三个已关闭的真实模型运行，保留两项已提交、一项未完成的原状态，资料不足题的空回答及附引用问题单独显示。当前资料库活跃版本已变化，四条旧PDF页引用仍可通过归档版本回读核对。这里没有新的模型任务成绩，也没有把导出成功算成一次模型成功。

报告生成阶段耗时2.067秒，两次导出的三份文件逐字节一致。网络连接尝试、新增生成请求、嵌入前向和GPU使用均为0；原运行目录、资料库、受保护账本和先前归档的哈希前后不变。[运行证据与保留的首次失败](../evidence/research-report/README.md)记录验证范围、源码和冻结归档。
