# 报告目录的词法检索

实际9B审计曾在读到必需报告后继续读取无关历史报告，最后耗尽轮次，未产生有效提交。[原失败与完整通信证据](mcp-agent.md)保持原样。新增可选的目录筛选，让 Agent 用问题关键词选择报告，再通过原 MCP 工具读取字段和提交事实。

`--catalog-policy bm25` 只对远端 `list_reports` 返回的 ID、描述和字段名排序；不访问报告正文、gold、隐藏路径或外部模型。默认模式仍返回完整目录。BM25使用固定k1=1.2、b=0.75，切分camel/snake标识符、过滤固定英文停用词；每个不同查询词计一次，不做同义词、词干化或中文分词。最多4份完整条目，整个结果JSON不超过4096 UTF-8字节，包含排序解释的开销。

词法匹配可能漏检。没有匹配时返回空结果；条目过大时明确记为因字节省略，不把截断内容当完整目录。模型可改用更具体查询，或 `list_reports(query="*")` 请求原完整目录。每次仍消耗一个正常MCP目录操作，远端仍按原实现核对完整目录各报告的字节；此优化只缩小模型看到的目录回复，不减少该次MCP传输或服务端文件核对。检索元数据不能支持事实引用，仍须取得原服务的读取回执；验证、清理、轮次和模型请求额度均沿用原实现。

该模式另提示模型在第六次回复前完成最终提交，为固定SDK的七轮边界留余量。目录筛选与规划提示一起改变了策略，后续即便成功，也不能单独归因于BM25。当前不更改默认策略，不宣称减少总HTTP字节、输入token、延迟或提高模型成功率。

```sh
# 授权服务器上的锁定MCP/Agent环境；使用新的state目录。
extras/mcp-agent/.venv/bin/python -m benchmarks.llamaindex_mcp_audit \
  --mcp-url http://127.0.0.1:18859/mcp \
  --cases evidence/mcp-agent/normal/cases.json --case supported_contribution \
  --state-dir /tmp/new-ranked-audit --base-url http://127.0.0.1:18858/v1 \
  --model YOUR_LOCAL_MODEL --owner "$PROTOCOL_SHA256" --catalog-policy bm25
```

目录可以使用[24份固定实际报告](../evidence/report-retrieval/corpus/catalog.json)：包含训练/生成、真实模型失败、文件系统与MCP工程检查，以及当前和历史贡献结果。原报告逐字节复制，来源提交固定在301220730b5c740ee847f0c119c02caf612b9f86。19个[预声明检索问题与人工相关性判断](../benchmarks/report_retrieval_cases.json)中2个是先前已见开发问题，其余17个也是操作者基于已知报告编写的诊断，不是盲测或独立模型应用验收。没有按检索结果调整参数或标签。

[服务器执行证据](../evidence/report-retrieval/README.md)分别报告完整目录、相同分词下不加IDF的关键词重合排序、BM25排序的报告覆盖和JSON字节。完整目录包含全部24条，可能超出4096字节；不把它伪装成等预算的低召回基线。检索评分只判断必需报告是否出现，既不证明字段覆盖、事实正确，也不验证模型自行选择或最终提交。七项模块控制与真实MCP/FunctionAgent脚本控制另列范围；脚本回复不是神经结果。

方法参考：Anthropic的[Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval)讨论了BM25对精确术语检索的作用。本实现只是目录元数据上的词法基线，没有复现其上下文生成、向量检索或重排系统。[2026年的代码表示研究](https://arxiv.org/abs/2607.11046)研究了表示选择与Agent定位质量/成本的关系；这是后续代码检索方向的参考，本次没有运行论文的Agentless、LCA或SWE-bench实验，也不引用其指标作为本人结果。

## 本轮实际结果

| 目录策略 | 19题中找齐必需报告 | 平均结果JSON字节 | 最大结果JSON字节 |
| --- | ---: | ---: | ---: |
| 完整目录，24条 | 19 | 5272 | 5272 |
| 相同分词的关键词重合排序，最多4条 | 19 | 1495.42 | 1790 |
| BM25，最多4条 | 19 | 1512.47 | 1808 |

两种词法排序都在4096字节上限内，**这组诊断没有显示BM25优于简单关键词基线**。人工描述、查询和相关性标签来自同一项目，问题较容易，不推断跨项目召回率。目录变短不证明模型会减少无关读取；更大的工具schema及后续查询也会消耗上下文。

七项模块控制通过；真实MCP/FunctionAgent的排序、显式完整目录回退、零匹配后回退三场控制通过，分别使用3/3/4次脚本模型POST，均核对读取回执、最终提交和同一审计关闭。原四场控制在旧适配器与新版默认模式各运行一次，每侧9次脚本POST，九份对应HTTP正文SHA逐一相同。没有新增神经调用，也没有重跑或改判历史9B失败、3B训练或生成评测。
