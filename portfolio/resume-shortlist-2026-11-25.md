# 简历项目精选 · 2026-11-25

建议一份简历重点写两个项目，再加一条开源贡献。算法与模型研发岗位优先选1＋2，Agent应用开发岗位优先选2＋3。以下是同一Agent Reliability Lab内的模块，按实际承担的工作修改措辞，不写成四个商业上线产品。

## 1. 工具调用模型的监督目标与误差分析

**PyTorch / Transformers / PEFT / Qwen2.5-3B / LoRA**

- 面向工具调用训练，审计数据复用与监督标签分布，构建固定模板损失掩码；实现相同初始化、输入顺序和设备条件下的LoRA配对训练，两组各完成32次更新。
- 建立生成输出与逐token损失双视角评测，完成750份固定生成输出和831次教师强制前向，区分结构、回答载荷与固定模板损失，并验证基座冻结和检查点重载。
- 实现持久调用预算和失败留痕，支持恢复与结果追溯；在200条正例上分析150/153的配对差异，保留“未证明稳定收益”的结论，明确下一轮实验条件。

适合讲清：为什么改变监督目标、如何控制变量、为什么损失下降不等于任务效果提升。当前不是完整多种子训练或已证实的精度提升。[详细总结与证据](project-summary-2026-11-24.md#1-工具调用模型的监督目标与可追溯评测)。

## 2. 可恢复、带论文页引用的本地研究助手

**LangGraph / AsyncSqliteSaver / LlamaIndex / MCP / multilingual-e5-small / 本地Qwen3-4B**

- 基于LlamaIndex/MCP构建本地多语论文库，接入三篇全文52页、240个片段；新增论文时复用旧148个向量，仅编码92个新增片段，引用绑定PDF哈希、物理页码及资料版本。
- 使用LangGraph/SQLite串联本地模型检索、原文读取和回答提交，实现持久调用额度、回复缓存与断点恢复；支持关闭模型后的批量阅读报告，交付已有回答、页引用和未完成原因。
- 在服务器CPU完成真实4B模型三项固定工作流，方法解释和跨论文比较两项有效提交，18次请求全部保存并保留失败题；完成结果重放和报告导出均不增加推理调用。

适合讲清：检索到、实际读取和陈述正确之间的区别；如何处理模型服务格式差异、未知调用及恢复。真实模型三题中资料不足题未完成有效提交；2/3为固定工作流的提交结果，不能当作QA准确率或可靠拒答证据。来源复核及每题约3–4分钟的CPU耗时见[运行说明](../docs/research-assistant.md)。LightRAG与MiniRAG是输入论文；此项目使用LlamaIndex等框架，不宣称复现它们的图检索算法或论文分数。

新增RECEIPT阅读问题单独验证：4次生成、2次查询嵌入，GPU为0，引用契约通过；对照原页后保留机制解释不完整的结论。[完整记录](../docs/frontier-reading.md)不与原三题混算准确率，也不宣称复现RECEIPT算法。

## 3. 面向开源维护的依赖升级审查Agent

**LangGraph / MCP / LlamaIndex FunctionAgent / SQLite / OSV-Scanner / uv**

- 将固定版本源码、依赖锁、漏洞库、候选解析和兼容测试串联为可审阅工作流；按八项事实条件输出带哈希与字段引用的JSON/Markdown审查报告。
- 基于LangGraph实现批量处理、SQLite断点恢复和JUnit证据绑定，校验测试ID、源码版本及扫描锁文件归属，避免候选与测试结果错配。
- 在Browser Use、FastMCP、LightRAG真实快照上验证不同维护情形；12项工作台测试与SIGKILL后新进程恢复通过，并将LightRAG的RAGAS锁定版本升级提交为正式PR。

适合讲清：升级候选如何产生、漏洞匹配消除为何不等于安全清零、兼容证据怎样绑定到具体源码。工作台为确定性流程，既有真实模型接入的验证单独报告；不声称模型自主完成全部维护。[使用及证据](../docs/dependency-workbench.md)。
